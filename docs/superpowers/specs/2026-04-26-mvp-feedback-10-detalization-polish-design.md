# Spec №10: Детализация / Сообщения — финальная UX-полировка

**Дата:** 2026-04-26
**Источник:** MVP-таблица, строка «Отследить → Детализация»
**Статус:** Сделано на ~85%. Закрываем оставшиеся 5 пунктов и решаем судьбу дубль-страницы.

## Контекст

Спека требует переименовать «Детализация» → «Сообщения», добавить расширенные фильтры, чипсики, экспорт, настройку колонок, сортировку, дефолтные столбцы.

Аудит показал, что [MessagesPage.tsx](portal-frontend/src/pages/messages/MessagesPage.tsx) уже почти всё реализует:
- Уже называется «Сообщения», text-muted есть.
- Primary-фильтры: даты, destination, login (только для reseller), status, operator, sender_name, channel.
- Secondary-фильтры (свернуты): message_id, send_method (PORTAL/API/SMPP), country.
- ActiveFilterChips работает.
- Кнопки «Найти»/«Сбросить», «Экспорт» (CSV через async job), пагинация 20/50/100.
- ColumnConfigurator с persist в localStorage.
- Счётчик «Найдено: N сообщений».
- Сортировка по: submitted_at, total_amount, created_at, status_at, segment_count.

Расхождения:
1. «Тип услуги (SMS/MAX)» в спеке — отдельный фильтр, в коде дублируется с фильтром «Канал».
2. Сортировки по статусу нет — спека её не упоминает явно, но в общем списке «по дате статуса» есть, по самому статусу как полю — нет.
3. Формат экспорта захардкожен `.csv`. Спека про формат молчит, но CSV без BOM ломает кириллицу в Excel.
4. ColumnConfigurator не подписан текстом «Настройка таблицы».
5. Существуют **две страницы**: `/messages` (новая клиентская) и `/admin/detalization` (старая админская). Дрейф между ними нарастает.

## Решение

### Что меняем

**1. «Тип услуги (SMS/MAX)» — оставить только «Канал»**

Спека дублирует одно и то же поле двумя именами. «Канал» (channel) — то же, что «Тип услуги» (service type) в нашем домене. Оставляем фильтр «Канал» на уровне primary, **удаляем** «Тип услуги» из secondary.

Лейбл «Канал» в UI оставить, добавить tooltip: «Тип услуги: SMS, MAX, Telegram, etc.».

**2. Сортировка по статусу**

В [MessageTable.tsx](portal-frontend/src/pages/messages/MessageTable.tsx) добавить `sortField: 'status'` для колонки «Статус». На бэке проверить что `sort_by=status` в `GET /portal/v1/detalization` принимается. Если не принимается — добавить в whitelist.

Сортировка лексикографическая по строковому значению статуса. Альтернатива (приоритет: delivered > sent > queued > failed) — отдельная задача, для MVP лексикография достаточна.

**3. Экспорт XLSX по умолчанию + CSV как fallback**

В UI заменить одну кнопку «Экспорт» на dropdown:
- «Экспорт в Excel (XLSX)» — дефолт.
- «Экспорт в CSV» — для интеграций.

XLSX через библиотеку на бэке (`github.com/xuri/excelize/v2` — стандарт в Go-экосистеме). Async job, как сейчас работает CSV.

CSV — генерировать с **BOM** (`\xEF\xBB\xBF` в начале файла), чтобы Excel правильно подхватывал кодировку UTF-8 кириллицы.

Лимит экспорта: **100 000 строк** на один экспорт. Если по фильтрам найдено больше — фронт показывает: «Найдено больше 100k строк. Сузьте фильтры (например, по периоду) или используйте API для bulk-выгрузки.» Лимит реализуется в worker'е экспорта (`exportApi.start`) — после 100k обрезаем и помечаем job как `truncated=true`.

**4. ColumnConfigurator — подписать**

Кнопку, открывающую ColumnConfigurator, явно подписать текстом «Настройка таблицы» (вместо иконки шестерёнки или безымянной кнопки). Иконку оставить рядом с текстом.

**5. Дубль-страница `/admin/detalization`**

Не объединяем сейчас (это L-задача с риском трогать админку). Стратегия:
- Скрываем `/admin/detalization` из admin-навигации.
- На странице `/admin/detalization` показываем баннер: «Этот раздел устарел и будет удалён. Используйте `/messages` (доступно админу с фильтром «По всем клиентам»).»
- На `/messages` для админа добавляем (если ещё нет) фильтр «Клиент» (по client_id) — это даёт админу те же возможности, что были в `/admin/detalization`.
- Через 1-2 спринта (отдельный спек): удаление `/admin/detalization` целиком.

### Что НЕ делаем

- **Объединение `/messages` и `/admin/detalization` в один компонент с режимами `viewMode`.** Слишком большой scope, риск задеть прод. Объединение — отдельный спек.
- **«Логин» в дефолтных колонках для одиночного клиента.** Бесполезная колонка с одним и тем же значением. Спека в этом пункте не учитывает кейс solo-клиента. Оставляем текущее поведение: «Логин» в дефолте только для reseller.
- **Дату-фильтр сбросить в «без ограничения».** Это убьёт БД при первом открытии у клиента с миллионами сообщений. Дефолт «последние 7 дней» оставляем.
- **«Тип услуги» как отдельный фильтр.** Дублирование. Если спека настаивает — менеджер пусть переформулирует как уточняющую группу подтипов внутри «Канал».

### Открытые вопросы (закрываю сам)

- **Формат экспорта:** XLSX дефолт + CSV (с BOM) альтернатива.
- **Лимит экспорта:** 100 000 строк. Без этого первый клиент с большим архивом положит worker.
- **Кому видна страница `/messages`:** клиенту/партнёру/админу. Roles guard уже это умеет — оставляем.
- **`/admin/detalization`:** скрываем из меню, баннер depreciation, удаление — отдельным спеком.

## Acceptance criteria

1. Фильтр «Тип услуги (SMS/MAX)» в secondary удалён. Tooltip на «Канал» поясняет суть.
2. Колонка «Статус» сортируется кликом по заголовку (asc/desc).
3. Кнопка «Экспорт» — dropdown с двумя опциями. XLSX скачивается с корректной кириллицей в Excel. CSV содержит UTF-8 BOM.
4. Если фильтры дают >100k строк — экспорт обрезает до 100k и UI показывает соответствующее предупреждение.
5. Кнопка ColumnConfigurator подписана текстом «Настройка таблицы».
6. `/admin/detalization` скрыта из admin-меню; на странице — баннер deprecation со ссылкой на `/messages`.
7. На `/messages` для роли admin доступен фильтр «Клиент» (выбор любого клиента).

## Размер задачи

M (2-3 рабочих дня: dropdown экспорта + XLSX worker на бэке + лимит + сортировка по status + lap по UI-надписям + баннер на admin/detalization).
