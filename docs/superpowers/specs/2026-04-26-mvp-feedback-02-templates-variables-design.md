# Spec №2: Шаблоны клиента — селектор переменных + удаление поля «Тип трафика»

**Дата:** 2026-04-26
**Источник:** MVP-таблица, строка «Отправить → Шаблоны»
**Статус:** Не сделано.

## Контекст

Шаблоны клиента (`portal-frontend/src/pages/templates/TemplatesPage.tsx`) — это шаблоны массовых рассылок. Они не модерируются операторами и не получают сниженного тарифа (см. вкладку «Словарь CTO CEO» в спеке). Поле «Тип трафика (Авторизационный / Сервисный / Транзакционный)» в этих шаблонах смысла не несёт — оно относится к **шаблонам операторов** (которые регистрируются у МТС/Билайн/etc).

Параллельно пользователю не хватает быстрого способа вставить переменную в текст шаблона: сейчас он должен вручную набирать `{{name}}`, помня имена.

Бэкенд (`internal/services/template/application/template_service.go:297` `RenderTemplate`) использует `strings.NewReplacer` — простую подстановку `{{key}}` → `value`. Условный синтаксис вида `Уважаем{ый|ая}` не поддерживается.

## Решение

### Что меняем

**На фронте:**
1. Убрать поле «Тип трафика» из формы создания/редактирования шаблона ([TemplatesPage.tsx:365-376](portal-frontend/src/pages/templates/TemplatesPage.tsx#L365)) и колонку «Тип трафика» в таблице ([TemplatesPage.tsx:267-279](portal-frontend/src/pages/templates/TemplatesPage.tsx#L267)).
2. Под textarea «Текст шаблона» вместо текстовой подсказки добавить ряд кнопок-чипов:
   `Уважаемый(ая) | Имя | Отчество | Фамилия | День рождения | Промокод`
3. По клику — вставить в позицию курсора:
   - «Уважаемый(ая)» → `Уважаем{ый|ая}` (литерал, без условного рендеринга)
   - «Имя» → `{{name}}`
   - «Отчество» → `{{lastname}}`
   - «Фамилия» → `{{firstname}}`
   - «День рождения» → `{{birthday}}`
   - «Промокод» → `{{promocode}}`
4. Под рядом — text-muted: «Значения подставляются из колонок контактной базы при отправке».

> ⚠️ Спека путает имена полей. Спецификация говорит «{{firstname}} → фамилия», «{{lastname}} → отчество». Это противоестественно (firstname обычно = имя). Я следую буквально спеке — менеджер позже может попросить пересмотреть мэппинг, тогда меняем только UI-чипы, без миграций.

**На бэке:**
1. Если в `templates` есть колонка `traffic_type` — пометить как deprecated, перестать читать в API. Удалять сейчас не будем (риск поломать существующие записи; убираем UI, БД оставляем). Миграция с DROP COLUMN — отдельная уборочная задача.
2. `strings.NewReplacer` оставить как есть — он отрендерит литерал `Уважаем{ый|ая}` как `Уважаем{ый|ая}` в SMS. Это и есть желаемое поведение для MVP.
3. Регистр поддерживаемых переменных в рендерере: `{{name}}, {{firstname}}, {{lastname}}, {{birthday}}, {{promocode}}`. Если каких-то нет — добавить (по умолчанию пустая строка, если в контакте поле не заполнено).

### Что НЕ делаем

- **Условный рендеринг по полу.** Это требует поля `gender` в `contacts`, парсера условного синтаксиса в рендерере, миграций БД, тестов. Объём задачи на 1-2 недели. Вне MVP. Если менеджеру нужно — отдельный спек после MVP.
- Удаление колонки `traffic_type` из БД. Чистка — позже.
- Глобальный реестр переменных как сущность. Сейчас — захардкоженный список 6 чипов в UI и 5 ключей в рендерере.

## Архитектура

```
TemplatesPage.tsx
├── (удалить) field "Тип трафика"
├── textarea "Текст шаблона"
└── (новый) <VariableChips onInsert={(token) => insertAtCursor(textareaRef, token)} />
    └── 6 кнопок: literal | template-token

internal/services/template/application/template_service.go
└── RenderTemplate
    ├── Replacer должен покрывать: name, firstname, lastname, birthday, promocode
    └── Уважаем{ый|ая} проходит как литерал — это OK
```

## Acceptance criteria

1. На странице «Шаблоны» (клиентский портал) нет поля «Тип трафика» ни в форме, ни в колонках таблицы.
2. Под textarea текста шаблона — 6 чипов с указанными лейблами.
3. Клик на чип вставляет соответствующий токен в позицию курсора (или в конец текста, если фокус не на textarea).
4. После сохранения шаблона и отправки сообщения с этим шаблоном через `RenderTemplate`:
   - `{{name}}` подменяется значением из колонки `name` контакта (или пустотой).
   - `{{firstname}}/{{lastname}}/{{birthday}}/{{promocode}}` — аналогично.
   - `Уважаем{ый|ая}` уходит в SMS как есть.
5. Существующие шаблоны (с заполненным `traffic_type` в БД) продолжают работать; UI просто игнорирует это поле.
