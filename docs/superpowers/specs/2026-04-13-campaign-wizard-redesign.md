# Campaign Wizard Redesign — Спецификация

**Дата:** 2026-04-13  
**Файл для изменения:** `portal-frontend/src/pages/campaigns/CampaignWizardPage.tsx`  
**Подход:** Рефакторинг существующего файла (подход A)

---

## Цель

Сократить визард создания SMS-кампании с 6 шагов до 4, убрав шаг повторов (retry) и объединив шаги Message + A/B Test в один. Упростить UX, не меняя бэкенд-архитектуру.

---

## Структура шагов

| # | Шаг | Что содержит |
|---|-----|-------------|
| 1 | Сообщение | Текст/шаблон, счётчик символов, имя отправителя, переключатель A/B + блок A/B |
| 2 | Аудитория | Выбор базы контактов с количеством, фильтры исключения (страна, оператор), сводка |
| 3 | Расписание | Сейчас / Позже + дата-время, чекбокс "часовой пояс абонента" |
| 4 | Подтверждение | Автоимя кампании (редактируемое), сводка всего, приблизительная стоимость, "Отправить" |

---

## Шаг 1: Сообщение

### Основной режим

- **Textarea** с текстом сообщения (placeholder: "Введите текст сообщения...")
- **Кнопка "Выбрать шаблон"** — открывает существующий `TemplatePicker`; при выборе шаблона текст подставляется в textarea
- **CharacterCounter** под textarea: символы + количество частей SMS (GSM7: 160/153 на часть, Unicode: 70/67)
- **SearchableSelect "Имя отправителя"** — загружается список одобренных sender names; первый выставляется по умолчанию
- **Тоггл "A/B тестирование"**

### Режим A/B (при активации тоггла)

Разворачивается панель "Вариант B":

- Textarea текст сообщения варианта B
- Кнопка "Выбрать шаблон" для варианта B (тот же TemplatePicker)
- CharacterCounter для варианта B
- **Слайдер/числовой input "Доля аудитории для теста"**: 5–50%, шаг 5%
- **Select "Время до выбора победителя"**: 1 ч / 3 ч / 6 ч / 12 ч / 24 ч
- **Radio group "Метрика победителя"**:
  - Процент доставки (`delivery_rate`)
  - CTR (`click_rate`)
  - Уникальный CTR (`unique_click_rate`)

### Валидация (canProceed для шага 1)

- Текст варианта A не пуст
- Имя отправителя выбрано
- Если A/B включён: текст варианта B не пуст, доля выбрана, время выбрано, метрика выбрана

### Удаляется из текущего кода

- Шаг "A/B Test" (текущий step 3) — логика переносится в шаг 1
- Шаг "Retry" (текущий step 5) — удаляется полностью, включая `retryConfig` из стейта и `setRetryConfig` API-вызов

## Шаг 2: Аудитория

### Выбор базы

- `SearchableSelect` со списком контактных баз
- Каждая опция отображает количество контактов: `"База клиентов (1 234)"`
- Данные о количестве берутся из поля `contact_count` существующего API `GET /portal/v1/contact-lists`

### Фильтры исключения

- Опциональный блок, раскрывается кнопкой "Добавить фильтры"
- **MultiSelect "Исключить страны"** — список стран определяется по префиксам номеров в выбранной базе. Если endpoint для получения уникальных стран/операторов по базе отсутствует — отображается статический список (RU, KZ, BY, UA, ...), а подсчёт исключений не производится до шага подтверждения
- **MultiSelect "Исключить операторов"** — аналогично (МТС, Билайн, МегаФон, ...)
- Фильтры передаются бэкенду при создании кампании в поле `segment_rules` (JSONB); реальная фильтрация на бэкенде

### Сводка (реактивная)

- Без фильтров: `Контактов к отправке: 1 234`
- С фильтрами: `Контактов к отправке: 1 089 (Исключено: 145)`
- Если A/B включён: `Тестовая группа: ~218 контактов (20%)`
- Подсчёт исключений — клиентский (приблизительный, на основе процентного соотношения)

### Валидация (canProceed для шага 2)

- База контактов выбрана

## Шаг 3: Расписание

### Режим отправки

Radio group:
- `Сейчас` — запуск сразу после создания кампании
- `Позже` — разворачивает поля даты и времени

### При выборе "Позже"

- Date picker + time picker "Дата и время отправки"
- Минимальное значение: текущее время + 5 минут
- Формат отображения: `13 апр. 2026, 14:30`

### Часовой пояс абонента

- Checkbox: "Доставить в указанное время по часовому поясу абонента"
- Tooltip: "Каждый получатель получит SMS в указанное время по своему часовому поясу, определённому по номеру телефона"
- Активен только при выборе "Позже"; при "Сейчас" — неактивен и снят

### Валидация (canProceed для шага 3)

- Если "Позже": дата/время заполнены и в будущем (> now + 5 мин)

### Маппинг на API

- "Сейчас": `scheduled_at: null`, после создания вызываем `POST /campaigns/{id}/launch`
- "Позже": `scheduled_at: "<ISO 8601>"`, `use_subscriber_timezone: bool`
- Если поле `use_subscriber_timezone` отсутствует в текущей модели бэкенда — добавить в `CreateCampaignRequest`

## Шаг 4: Подтверждение

### Название кампании

- Автозаполненное значение: `SMS · DD.MM.YYYY · HH:mm` (по дате/времени отправки или по дате создания при "Сейчас")
- Кнопка-иконка карандаша → inline редактирование (input с blur-сохранением)

### Сводка (только чтение)

Каждый блок содержит кнопку-иконку для перехода на соответствующий шаг:

**Сообщение** [→ шаг 1]:
- Текст (обрезан до 100 символов + "...")
- Имя отправителя

**A/B тестирование** (если включено) [→ шаг 1]:
- Текст варианта B (обрезан)
- Тестовая доля: `20%`
- Время теста: `6 часов`
- Метрика: `Процент доставки`

**Аудитория** [→ шаг 2]:
- Название базы · `1 089 получателей`
- Если фильтры: `Исключено: 145 (RU МТС)`

**Расписание** [→ шаг 3]:
- `13 апр. 2026, 14:30` или `Сейчас`
- `По часовому поясу абонента: Да/Нет`

**Стоимость (приблизительно)**:
- Расчёт: `кол-во_получателей × частей_SMS × стоимость_1_SMS`
- Стоимость 1 SMS берётся из существующего `estimate-cost` endpoint или из настроек клиента
- Баланс пользователя
- Если баланс >= стоимость: зелёная галочка "Достаточно"
- Если баланс < стоимость: предупреждение "Недостаточно средств", кнопка "Отправить" неактивна

### Логика "Отправить" / "Запланировать"

Последовательные API-вызовы:

1. `POST /campaigns` → `{id}`
2. Если A/B включён:
   - `PUT /campaigns/{id}/variants`
   - `PUT /campaigns/{id}/ab-config`
3. Если `scheduled_at: null` (режим "Сейчас"): `POST /campaigns/{id}/launch`
4. Редирект на `/campaigns/{id}`

При ошибке на любом шаге — показываем toast с сообщением ошибки, кнопка снова активна.

## Навигация и черновики

### Кнопки на каждом шаге

| Кнопка | Действие |
|--------|----------|
| "Отмена" | Открывает ConfirmDialog: "Сохранить как черновик" / "Не сохранять" |
| "Сохранить как черновик" | `POST /campaigns` с `status: draft`, редирект на `/campaigns` |
| "Назад" (шаги 2–4) | Переход на предыдущий шаг |
| "Далее" (шаги 1–3) | Валидация + переход вперёд |
| "Отправить" / "Запланировать" (шаг 4) | Создание и запуск кампании |

### Открытие черновика

При переходе на `/campaigns/new?draft={id}` — загружаем черновик через `GET /campaigns/{id}` и заполняем стейт визарда. Переходим сразу на шаг 1.

### Клик по пройденным шагам в StepIndicator

Разрешён переход назад без валидации. Переход вперёд — только через "Далее" с валидацией.

## Открытые вопросы

1. **`use_subscriber_timezone`** — есть ли это поле в текущей бэкенд-модели кампании? Если нет — нужно добавить на бэкенде.
2. **Фильтры по стране/оператору** — есть ли endpoint для получения уникальных стран/операторов в конкретной базе контактов? Если нет — первая итерация использует статический список.
3. **Стоимость 1 SMS** — как получить текущую стоимость для клиента? Через `estimate-cost` с минимальными параметрами или отдельный endpoint тарификации?

## Что НЕ входит в scope

- Шаг "Повторы" (retry) — удаляется полностью, без замены
- Каскадная доставка в визарде — отдельная фича
- Мобильная адаптация — визард остаётся десктопным
- Изменения бэкенда, кроме поля `use_subscriber_timezone` если его нет
