# SMS Gateway as a Service — Дизайн бизнес-модели

**Дата:** 2026-03-27
**Статус:** Утверждён

## 1. Позиционирование и рынок

### Продукт

«SMS-шлюз как сервис» (SMS Gateway as a Service) — облачная SaaS-платформа, где клиент за 10 минут получает полноценный SMS-шлюз: подключает своих SMPP-провайдеров, настраивает маршрутизацию, биллинг и начинает отправлять. Клиент приходит со своими договорами с операторами — платформа даёт инструменты для управления трафиком.

### Конкурентная среда

| Категория | Примеры | Почему не конкурент |
|---|---|---|
| SMS-агрегаторы | Devino, SMS.ru, SMSC.ru | Продают трафик, не платформу. Клиент не может подключить своих провайдеров |
| Open-source шлюзы | Kannel, Jasmin | Устарели (Kannel — C, 2000-х; Jasmin — Python, медленный). Нет UI, биллинга, аналитики |
| Western platforms | Melrose Labs, Monty Mobile | Дорого ($5-20K/мес.), не локализованы, санкционные риски |
| Самописные решения | Внутренние платформы агрегаторов | Стоят миллионы в разработке, нет на рынке как продукт |

**Ниша:** современная российская платформа для запуска SMS-бизнеса или управления SMS-инфраструктурой без разработки с нуля.

### Целевые сегменты

1. **Начинающие SMS-реселлеры** — предприниматели с договорами с 1-2 операторами, которым нужна платформа «из коробки»
2. **Мелкие агрегаторы** — работают на самописных или устаревших решениях, хотят модернизироваться
3. **Компании с прямыми SMPP-подключениями** — банки, финтех, маркетплейсы с прямыми договорами с операторами

## 2. Тарифная сетка и модель дохода

### Три источника дохода

#### 2.1 Подписка (фиксированная часть)

| План | Цена/мес. | Что включено |
|---|---|---|
| **Starter** | 5 000 руб. | 1 SMPP-подключение, 50 000 SMS/мес., базовая аналитика, 1 пользователь |
| **Business** | 15 000 руб. | 5 SMPP-подключений, 300 000 SMS/мес., HLR-кеш, smart-routing, 5 пользователей, вебхуки |
| **Pro** | 40 000 руб. | Безлимит подключений, 1 500 000 SMS/мес., продвинутая аналитика, тарификация с 4 стратегиями, суб-аккаунты, приоритетная поддержка |

#### 2.2 Оплата за объём сверх лимита

| Сверх лимита плана | Цена за SMS |
|---|---|
| До 500 000 | 0.015 руб. |
| 500 000 — 2 000 000 | 0.010 руб. |
| 2 000 000+ | 0.007 руб. |

Плата за инфраструктуру (процессинг, хранение, мониторинг), не за трафик.

#### 2.3 Платные дополнения (add-ons)

| Дополнение | Цена/мес. |
|---|---|
| HLR-валидация (standalone API) | 3 000 руб. + 0.05 руб./запрос |
| White-label портал (свой домен, лого) | 10 000 руб. |
| Выделенный Grafana-дашборд | 5 000 руб. |
| SLA 99.9% + приоритетная поддержка | 15 000 руб. |
| Дополнительное хранение истории (>3 мес.) | 2 000 руб./мес. за +3 мес. |

#### 2.4 Бесплатный тариф (опционально)

Free / Trial — 1 000 SMS/мес., 1 подключение, без аналитики. Конверсия в платный план: 5-10% для B2B SaaS.

### Юнит-экономика (пример)

Клиент на Business, 500 000 SMS/мес.:
- Подписка: 15 000 руб.
- Сверх лимита (200 000 SMS): 3 000 руб.
- HLR add-on: ~5 500 руб.
- **Итого: ~23 500 руб./мес.**
- Расходы на клиента: ~2 000-3 000 руб./мес.
- **Маржа: ~85-90%**

## 3. Востребованный функционал и приоритеты

### Tier 1 — Must-have (без этого не купят)

| Функция | Статус | Почему критично |
|---|---|---|
| SMPP-коннектор к провайдерам | Есть | Без этого платформа бесполезна |
| HTTP API для отправки | Есть | Основной способ интеграции |
| Маршрутизация по оператору | Есть | Отправка через разных провайдеров по правилам |
| Статусы доставки (DLR) | Есть | Без отчётов никто не будет работать |
| Личный кабинет клиента | Есть | Self-service обязательно для SaaS |
| Биллинг / баланс | Есть | Клиенты реселлеров видят баланс и расход |
| API-ключи и аутентификация | Есть | Безопасность, мультитенантность |

### Tier 2 — Продающие фичи (двигают на Business/Pro)

| Функция | Статус | Почему продаёт |
|---|---|---|
| Smart-routing (HLR + стоимость + availability) | В разработке | Экономит 15-30% на трафике |
| Тарификация с 4 стратегиями | В разработке | Реселлерам критично для биллинга |
| Суб-аккаунты (reseller model) | В спеке | Реселлер подключает своих клиентов |
| Вебхуки | Есть | Интеграция с CRM, ERP |
| Grafana-мониторинг | В разработке | Профессиональные клиенты хотят метрики |

### Tier 3 — Nice-to-have (удерживают клиентов)

| Функция | Статус | Почему важно |
|---|---|---|
| White-label портал | Нужно доработать | Реселлеры хотят свой бренд |
| Шаблоны сообщений | Есть | Удобство для массовых рассылок |
| Экспорт отчётов (CSV/PDF) | Нужно доработать | Бухгалтерия и отчётность |
| 2FA | Есть | Комплаенс для банков |
| Массовая отправка (batch) | Есть | Маркетинговые рассылки |

### Tier 4 — Будущее развитие (год 2)

| Функция | Зачем |
|---|---|
| Viber/WhatsApp/Telegram каналы | Омниканальность, средний чек x2-3 |
| Каскадная доставка | Экономия клиентам |
| REST API v2 + OpenAPI + SDK (Python, PHP, JS) | Снижает порог интеграции |
| Встроенный конструктор рассылок | Привлекает маркетологов |

### Порядок вывода на рынок

```
MVP для продажи (месяц 1-2):
  Tier 1 (уже есть) + стабилизация + onboarding flow

Первые платные клиенты (месяц 3-4):
  + Тарификация + суб-аккаунты

Рост до 20-30 клиентов (месяц 5-8):
  + Smart-routing + Grafana + white-label

Масштабирование (год 2):
  + Омниканальность + SDK + конструктор рассылок
```

## 5. Технические доработки для запуска SaaS

### 5.1 Мультитенантная изоляция

| Что | Зачем |
|---|---|
| Изоляция данных между тенантами на уровне БД | Клиент не должен видеть чужие данные |
| Rate-limiting per tenant | Один клиент не должен положить платформу |
| Квоты на ресурсы (SMPP-соединения, msg/sec) | Привязка к тарифному плану |
| Tenant-aware логирование | Поддержка и дебаг по конкретному клиенту |

### 5.2 Onboarding и self-service

| Что | Зачем |
|---|---|
| Регистрация + выбор плана + оплата | Начать работать за 10 минут без участия оператора |
| Wizard подключения SMPP-провайдера | Пошаговый UI: хост, порт, логин, пароль → тест → готово |
| Интерактивная документация API (OpenAPI) | Интеграция без звонков в поддержку |
| Тестовый режим (sandbox) | Отправка в «песочницу» — снижает страх попробовать |

### 5.3 Коммерческая обвязка

| Что | Зачем |
|---|---|
| Биллинг платформы (ЮKassa / CloudPayments) | Выставление счетов за подписку и объём |
| Оферта и SLA | Юридическая база для продажи |
| Лендинг + тарифы | Конверсия посетителей в регистрации |
| Система тикетов / чат поддержки | Минимальная поддержка (Telegram-бот или Crisp/Intercom) |

### 5.4 Приоритет доработок для MVP

```
Неделя 1-2:  Tenant isolation + квоты + rate-limiting per tenant
Неделя 3-4:  Регистрация + onboarding wizard + sandbox
Неделя 5-6:  Биллинг платформы (подписки, оплата)
Неделя 7-8:  Лендинг + документация API + оферта
```
