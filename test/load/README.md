# Load Tests

Нагрузочные тесты для проверки производительности системы под нагрузкой.

## Требования

Для запуска load тестов необходимо:

1. **API Gateway** - запущенный и доступный на `http://localhost:8080`
2. **Валидный API ключ** - для аутентификации запросов

## Запуск тестов

```bash
# Все load тесты
go test -tags=load ./test/load/...

# Конкретный тест
go test -tags=load -v ./test/load/... -run TestAPIGateway_Load

# Бенчмарки
go test -tags=load -bench=. ./test/load/...
```

## Типы тестов

### TestAPIGateway_Load

Базовое нагрузочное тестирование:
- Параллельность: 10 горутин
- Запросов на горутину: 100
- Всего запросов: 1000

Проверяет:
- Общую производительность
- Процент успешных запросов (должен быть > 95%)
- Throughput (запросов в секунду)

### TestAPIGateway_Stress

Стресс-тестирование с увеличивающейся нагрузкой:
- Warm up: 5 горутин, 10 секунд
- Normal load: 20 горутин, 30 секунд
- High load: 50 горутин, 30 секунд
- Peak load: 100 горутин, 20 секунд

Проверяет поведение системы при постепенном увеличении нагрузки.

### BenchmarkAPIGateway_SendSMS

Бенчмарк для отправки SMS:
- Измеряет время выполнения одного запроса
- Используется для сравнения производительности

## Настройка

Можно изменить параметры в файле `api_load_test.go`:

```go
const (
    apiBaseURL = "http://localhost:8080"  // URL API Gateway
    apiKey     = "test-api-key"           // API ключ для аутентификации
)
```

## Результаты

Тесты выводят:
- Общее количество запросов
- Количество успешных запросов
- Количество неудачных запросов
- Длительность выполнения
- Throughput (запросов в секунду)
- Процент успешных запросов

## Использование k6

Для более продвинутого нагрузочного тестирования можно использовать k6:

```bash
# Установка k6
# Windows: choco install k6
# Linux: https://k6.io/docs/getting-started/installation/

# Запуск теста
k6 run scripts/k6_load_test.js
```

Пример скрипта для k6 находится в `scripts/k6_load_test.js`.

## Рекомендации

1. Запускайте load тесты на отдельном окружении
2. Мониторьте ресурсы системы во время тестов
3. Используйте результаты для оптимизации производительности
4. Сравнивайте результаты между версиями
