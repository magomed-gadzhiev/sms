SMPP Wizard — архитектура

Выбери подход к реализации 6-шагового мастера

A

Отдельная страница /providers/new

Новый роут в portal. Прогресс сохраняется в URL-параметрах (?step=3). Шаги — отдельные React-компоненты. Можно обновить страницу без потери прогресса.

Плюсы

  • История браузера (назад/вперёд)
  • Легко тестировать каждый шаг
  • Простой layout — full-width форма

Минусы

  • Покидает страницу /providers
  • Дополнительный роут
B

Full-screen Modal

Overlay поверх ProvidersPage. Состояние в useReducer. Прогресс-бар в шапке модала. Закрыть = выйти из wizard (с подтверждением).

Плюсы

  • Контекст не теряется
  • Нет изменения роута
  • Похоже на SaaS-платформы (Stripe, Twilio)

Минусы

  • Нельзя обновить страницу
  • Сложнее управлять фокусом (a11y)
C

Slide-out Drawer

Правая панель поверх провайдеров. Узкий (~480px). Список провайдеров остаётся виден.

Плюсы

  • Список провайдеров виден
  • Быстрый dismiss

Минусы

  • Мало места для шага "Routing"
  • Шаг "Тест" с real-time выводом неудобен в узкой панели

Мои рекомендация — A: отдельная страница. Wizard с 6 шагами и live-тестом требует пространства и URL-навигации.
