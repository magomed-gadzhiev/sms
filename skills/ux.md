## Алгоритм анализа

> Если **Режим: audit** — полный анализ всех секций, результат — отчёт.
> Если **Режим: debug** — фокус на секциях 3 (Negative Path) и 5 (Feedback & States), результат — отчёт.
> Если **Режим: review** — фокус на секциях 4 (Interface Gap) и 6 (Права доступа), результат — отчёт.
> Если **Режим: fix** — полный анализ всех секций. Каждую найденную проблему исправлять немедленно в коде, не дожидаясь завершения анализа. Результат — список `[FIXED] было → стало` без развёрнутого отчёта.
> Если **Проверка инфраструктуры: yes** — добавить секцию 7.

### 1. Цель пользователя
Сформулируй одним предложением: "Что пользователь хочет сделать и почему?"
Не смотри код, пока не ответил на этот вопрос.

### 2. Happy Path — путь наивного пользователя
Проследи путь: UI-компонент → API-вызов → БД.
Для каждого шага ответь:
- Понятно ли название поля без документации?
- Сколько кликов до результата? (норма: ≤3 для типовой операции)
- Есть ли подтверждение успешного завершения?

### 3. Negative Path — граничные случаи
Проверь каждую форму/действие:
- Пустые обязательные поля
- Невалидные данные (спецсимволы, слишком длинный текст, отрицательные числа)
- Повторная отправка (двойной клик, F5 после POST)
- Отмена на середине операции

### 4. Interface Gap — разрыв API vs UI
- Какие параметры есть в API, но недоступны в интерфейсе?
- Какие поля есть в UI, которых нет в API (мёртвые элементы)?

### 5. Feedback & States
Для каждого асинхронного действия:
- Loading state: есть ли индикатор?
- Error state: понятное ли сообщение об ошибке (не "500 Internal Server Error")?
- Empty state: что видит пользователь, когда данных нет?

### 6. Права доступа
- Видит ли пользователь только свои данные?
- Можно ли через UI получить доступ к ресурсам другого аккаунта?
- Соответствуют ли кнопки/пункты меню реальным правам (нет кнопок без действия)?

### 7. Проверка инфраструктуры (только если `Проверка инфраструктуры: yes`)
- **API-эндпоинты:** существуют ли все вызываемые из UI эндпоинты в Go-хендлерах?
- **Миграции БД:** есть ли нужные таблицы/колонки в схеме?
- **Redis:** используется ли кеш/сессии корректно (TTL, инвалидация)?
- **Kafka:** если модуль публикует события — есть ли консьюмер?
- **gRPC:** соответствуют ли proto-контракты фактическим вызовам из portal-сервиса?
